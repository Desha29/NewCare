# NewCare Phase 2 Implementation Plan

> For agentic workers: use executing-plans to implement this plan task by task.

**Goal:** Deliver the Figma experience as a running, localized, adaptive Flutter application in D:\Work\NewCare, with official branding and version control.

**Architecture:** Feature-first data and presentation layers. Cubits own state; abstract repositories define data contracts; models represent serializable records. Repository injection and composable widgets implement dependency inversion. No entities or use-case layer, as explicitly requested.

**Stack:** Flutter stable, flutter_bloc/Cubit, intl + generated ARB localization, locally bundled Cairo, persistent local workspace repository. Supabase integration is a separate configured adapter and must not imply a live backend without credentials.

**Spec:** docs/design/NewCare-plan-ar.md and the NewCare Figma file OEygfKSLA6bHRDFb1cmVBE.

## Constraints

- Arabic RTL and English LTR. Every visible interface string is localized.
- Shared nursing device, manager-only administrative area. A preview must never be presented as production authentication.
- Cases belong to a staff member and shift; outside address required, phone optional; wallet does not change cash drawer.
- Breakpoints: compact <600, medium 600–1199, expanded >=1200; constrain forms and adapt table/card layouts.
- Use official logo and derived app icon without distorting their aspect ratios.
- Keep all changes within the new project, and create a private GitHub repository if authorized access is available.

## Tasks

1. Branding: prepare transparent full logo + square app icon, add reusable logo assets to Figma, replace placeholder branding, review mobile and desktop compositions.
2. Scaffold: create native platform folders, dependencies, local Cairo, ARB generation, theme, router/navigation state, responsive shell, configuration examples and CI.
3. Persistence and rules: model staff/cases/shifts/cash/catalogue/roles; repository interface and file-backed local implementation; test wallet separation, outside-address validation, shift membership, reconciliation and durable reload before adding UI behavior.
4. Nursing: implement picker/start, active shift, inside/outside forms, details, case history, cash movements, end shift, matched/variance handover, join staff and pending local state.
5. Manager: implement overview/date range, shifts, cases, payroll/advances, staff editor, catalogue editor, permission settings, login/setup, reports/export and audit/conflict UI.
6. Verify: analyze, behavior tests, Arabic/English widget tests at phone/tablet/desktop dimensions, web release build, visual browser comparison, icon generation and repository diff review.

## Review focus

- Small widths and large text must remain usable without overflow.
- No live financial or medical data is seeded; preview data must be clearly labeled.
- Local persistence must not imply cloud synchronization.
- Navigation to manager screens must be gated in the UI; production identity/security is a separate backend milestone.
- App configuration must not include service-role credentials or personal access tokens.

## Ledger

- Flutter 3.47.8 and Dart 3.13.7 available. Web and Android toolchains installed. Windows native compilation unavailable until Visual Studio C++ is installed.
- Ruling: use Arabic by default and persist language selection; English available from header/settings.
- Ruling: no Supabase service provisioning or production connection without a selected project/configuration. This phase delivers working local behavior and an explicit integration boundary.
- GitHub browser creation was denied by the browser origin approval gate. Do not work around that denial; finish the local repository and report remote creation as blocked unless the user changes authorization.
