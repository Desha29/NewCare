# NewCare — خطة التصميم والتنفيذ

تاريخ المراجعة: ٢٨ أكتوبر ٢٠٢٦

ملف التصميم: https://www.figma.com/design/OEygfKSLA6bHRDFb1cmVBE

## النطاق

تطوير نفس ملف Figma بهوية الكحلي والـteal وخط Cairo وواجهة عربية RTL. يتضمن مسارات التمريض والمدير على Desktop وTablet وMobile. الشاشات قابلة للتحرير، والأرقام والبيانات المعروضة أمثلة توضيحية. تصميم Figma لا يثبت تنفيذ الحماية أو المزامنة فعليًا.

## قواعد العمل

- جهاز المركز مفتوح للتمريض بدون حساب شخصي. اختيار الاسم يحدد صاحب الحالة ولا يثبت هوية الشخص الذي لمس الجهاز.
- أول تشغيل: إنشاء حساب المدير، ثم إضافة التمريض والإجراءات والمستلزمات ورصيد الدرج الافتتاحي. يدعم النظام أكثر من مدير.
- شيفت واحد نشط للدرج على جهاز المركز في الإصدار الأول؛ عدة أفراد تمريض يشاركون فيه. البدء والانتهاء بالتوقيت الفعلي، بدون اختيار صباحي/مسائي/ليلي.
- كل حالة مرتبطة بالشيفت وبفرد تمريض موجود فيه. يمكن للمدير الظهور ضمن التمريض بشارة «مدير».
- الحالة الداخلية: عنوان، إجراء، مستلزمات وكميات، مبلغ مدفوع، كاش أو محفظة، صاحب الحالة. لا عنوان مكاني أو هاتف.
- الحالة الخارجية: نفس البيانات مع عنوان مكاني إلزامي يظهر أولًا، وهاتف اختياري.
- لا يفترض التصميم وجود تطبيق مستقل للزيارات المنزلية. يمكن تسجيل الزيارة من جهاز المركز باسم المسؤول عنها.
- لا تعرض مساحة التمريض إجماليات الإدارة أو المرتبات. تظهر بيانات الدرج الضرورية فقط عند الاستلام.

## المسارات

1. إعداد أول مدير ← إضافة التمريض ← إعداد الإجراءات والمستلزمات ← رصيد الدرج ← بدء العمل.
2. اختيار اسم فاتح الشيفت ← عدّ نقدية الشيفت السابق ← مطابقة أو تسجيل فرق وسبب ← تأكيد الاستلام وبدء الشيفت.
3. الشيفت الحالي ← حالة داخلية/خارجية ← اختيار صاحب الحالة ← تفاصيل الإجراء والدفع ← حفظ ← تأكيد الحفظ.
4. الشيفت الحالي ← إنهاء ← مراجعة عدد الحالات وتقسيمها على التمريض وملاحظات التسليم ← جاهز للاستلام.
5. دخول المدير بكلمة مرور ← لوحة التحليلات ← تقارير بفترة مخصصة/شيفتات/حالات/مرتبات وسلف/تمريض/إجراءات/صلاحيات.

## الدرج والتسليم

النقدية المتوقعة = رصيد البداية + كاش الحالات + الوارد النقدي الآخر − المصروف النقدي − السلف النقدية − أي صرف نقدي آخر مسجل.

مدفوعات المحفظة لا تدخل الدرج. كل سلفة تُنشئ حركة مالية واحدة مرتبطة بها، فلا تُخصم مرتين. فرق الاستلام = الفعلي − المتوقع؛ السبب مطلوب عند وجود فرق. يحتفظ النظام بالقيمتين ومقدم التسليم والمستلم والتوقيت، ويرسل الفرق لمراجعة المدير. التصحيح بعد إغلاق الشيفت يسجل كتعديل ذي أثر واضح، ولا يمحو السجل الأصلي.

اقتراح الإصدار الأول: السماح باستلام الشيفت مع فرق موثق وإظهاره كمراجعة معلقة؛ لا يعطل الفرق بدء الرعاية. حد الفرق الذي يحتاج موافقة فورية قرار تشغيلي لم يُحدد بعد.

## الشاشات والمقاسات

- Desktop: عرض 1440 مع قائمة جانبية يمينًا.
- Tablet: عرض 1024 مع قائمة جانبية أخف؛ الجداول متاحة عندما تتسع الشاشة.
- Mobile: عرض 390، تنقل سفلي، بطاقات بدل الجداول الواسعة، حقول رأسية وتمرير للنماذج الطويلة.
- استخدام ألوان ومتغيرات الملف الحالية ومكونات الأزرار الحالية. لا توجد صورة شعار أصلية في المواد المتاحة؛ كلمة NewCare الحالية معالجة نصية وليست إعادة رسم للشعار.
- صفحات الملف القديمة محفوظة للمقارنة؛ الشاشات المحدثة تحمل أسماء مرقمة بعلامة «·»، وثلاث شاشات المدير المحدثة تحمل v2.

## حالة الاتصال

التصميم يشمل متصل، محفوظ على الجهاز، عمليات معلقة، تعارض يحتاج مراجعة، وتمت المزامنة. في التنفيذ: حفظ محلي متين قبل إظهار النجاح، طابور مزامنة، معرفات عمليات فريدة، وإعادة المحاولة بدون تكرار الحالة أو الحركة المالية. يعرض التعارض نسختين للمراجعة بدل إسقاط تعديل بصمت.

الإصدار الأول يفترض جهاز مركز واحد لكل درج أثناء الانقطاع. دعم أجهزة متعددة تعدل نفس الدرج دون اتصال يحتاج بروتوكول ملكية ومصالحة إضافيًا. إعداد الحسابات ودخول مدير جديد يحتاج اتصالًا؛ سياسة وصول مدير سبق التحقق منه أثناء الانقطاع تُحسم قبل البرمجة.

## الصلاحيات

اقتراح الأدوار: مدير رئيسي، مدير مالي، مدير تشغيل. الصلاحيات مستقلة لعرض الإجماليات، التقارير، المرتبات، السلف، إدارة التمريض، الإجراءات، تعديل شيفت مغلق، وإدارة المديرين. لا يمكن حذف آخر مدير رئيسي.

الحماية تنفذ في قاعدة البيانات والخدمات، وليس بإخفاء عناصر الواجهة وحده. وضع التمريض المشترك لا يملك صلاحية قراءة بيانات المدير المالية؛ يلزم نطاق وصول خاص بجهاز المركز. دخول المدير يفتح جلسة منفصلة تُقفل عند الرجوع للتمريض. أي ذاكرة محلية مالية تحتاج عزلًا وحماية. اختيار اسم ممرض ليس مصادقة ولا يصلح وحده كدليل هوية.

## بنية Flutter وSupabase المقترحة

- وحدات: الإعداد، جلسة الجهاز، التمريض، الشيفتات والتسليم، الحالات، الدرج، المرتبات والسلف، التحليلات، الأدوار، والمزامنة.
- لكل وحدة فصل العرض عن منطق العمل وعن مصادر البيانات، مع واجهات مستودعات واضحة. تُعاد الاستفادة من المكونات حسب المقاس.
- مصدر محلي وطابور عمليات للعمل اليومي، ومصدر Supabase للمزامنة والنسخ المشتركة.
- كيانات مبدئية: centers، devices، managers، roles، permissions، nursing_staff، shifts، shift_members، cases، case_supplies، procedures، supplies، cash_transactions، advances، handovers، audit_events، sync_operations.
- معاملات قاعدة البيانات تحمي: فتح الشيفت، إنهاءه، استلام الدرج، صرف السلفة، ومنع تكرار العمليات. سياسات الوصول تعزل المركز ودور الجهاز والمدير.
- لا اختيار نهائي لمكتبة قاعدة البيانات المحلية أو آلية مزامنة جاهزة قبل التحقق من المنصات المستهدفة وحماية البيانات وسيناريو تعدد الأجهزة.

## مراحل التنفيذ ومعايير القبول

1. **اعتماد الفلو:** تجربة البروتوتايب واستلام الدرج مع تطابق/عجز، ومراجعة نموذج الزيارة الخارجية. توثيق قرارات الحسابات والمرتبات.
2. **الأساس والصلاحيات:** إعداد مدير أول وإضافة مدير ثانٍ وتجهيز الجهاز والتمريض. التأكد أن جهاز التمريض لا يستطيع قراءة إجماليات المدير حتى بطلب مباشر.
3. **التشغيل اليومي:** بدء شيفت، إضافة أكثر من تمريض، حفظ حالات داخلية وخارجية وصرف/وارد. رفض الخارجية بلا عنوان، والسماح بلا هاتف.
4. **التسليم والدرج:** إنهاء وحساب الحالات لكل تمريض، فصل الكاش عن المحفظة، استلام مع فرق وسبب، ومنع أي قيد مالي مكرر.
5. **العمل دون اتصال:** إغلاق التطبيق وإعادة فتحه لا يفقد حالة محفوظة؛ إعادة المحاولة لا تنشئ نسخة ثانية؛ تجربة التعارض واسترداد المزامنة.
6. **الإدارة:** فترة مخصصة، تقارير ورسوم مرتبطة بنفس الفترة، مرتبات وسلف وفق قواعد متفق عليها، سجل تدقيق، وصلاحيات قابلة للتجربة.
7. **مراجعة الاستخدام:** RTL، تدرج الخطوط، استجابة المقاسات الثلاثة، وضوح حالة الحفظ، واختبار جلسة تمريض كاملة قبل الاعتماد.

## قرارات لم تُحدد في المتطلبات

- طريقة حساب المرتب: ثابت/ساعة/شيفت/حالة، والاستقطاعات والتسويات. أرقام المرتبات في التصميم توضيحية.
- السماح للتمريض بصرف مصروف أو سلفة وحده، وحدود المبالغ التي تحتاج اعتمادًا.
- عدد أجهزة المركز، وإمكانية تسجيل الزيارة من جهاز خارجي؛ افتراض التصميم الحالي جهاز واحد للدرج.
- مهلة قفل جلسة المدير، وإتاحة الإدارة أثناء الانقطاع، وسياسة الاحتفاظ والنسخ الاحتياطي للبيانات.
- ملف الشعار الأصلي للاستخدام النهائي.

## نتيجة جلسة التصميم

تم إنشاء ٨٧ شاشة محدثة: ١٤ للتمريض و١٥ للمدير لكل مقاس من المقاسات الثلاثة. أضيف التاريخ والوقت إلى هيدر كل شاشة. صفحة Flows تتضمن ثلاث لوحات للتشغيل والخطة وقواعد التنفيذ. المسودات السابقة محفوظة في Archive - Previous screens داخل نفس الملف.

تمت مراجعة نماذج من المقاسات الثلاثة بصريًا، وفحص وجود هيدر الوقت والتاريخ وصلاحية وجهات التنقل داخل كل صفحة وعدم وجود نصوص بعرض منهار. الروابط بين مساحة التمريض والمدير تفتح بروتوتايب الصفحة المقابلة في تبويب جديد، لأن Figma لا يدعم انتقال NAVIGATE بين صفحتي تصميم مختلفتين. النماذج والرسوم قابلة للتحرير؛ إجراءات الحفظ والدخول والمزامنة أمثلة تصميم وليست خدمات منفذة.

لينك Claude لم يكن متاحًا لأداة القراءة، لذلك المرجع هو ملخص المتطلبات المرسل وملف Figma نفسه.
